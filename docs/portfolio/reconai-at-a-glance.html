How to sign in

You don't. There is no account, no password and no database — which is the honest design for a tool that handles other companies' invoices. Nothing about your documents is stored anywhere after the page closes.

  1. Clone the repository and run npm install.
  2. Copy .env.example to .env.local and put an Anthropic API key in it.
  3. Run npm run dev and open localhost:3000.
  4. Want to see it work without a key at all? Press Preview sample output on the page. That runs the real reconciliation engine in your browser against a built-in invoice that has five deliberate errors in it — the same code path, just with the AI's matching step pre-supplied.

That last button is the point worth noticing: because the deciding half of this program needs no network and no model, it can be demonstrated honestly with the model switched off.

How it works

1. Read the bill

Claude transcribes every line exactly as printed — deliberately without correcting anything that looks wrong.

2. Pair up the lines

"Wheel stops – replace" on the bill and "Wheel stop replacement" on the order are the same job. Matching that is the one thing the AI is trusted with.

3. Redo every sum

Plain code recalculates the arithmetic, totals the overbilling and returns the verdict. No model is involved in any number.

This is exactly the job an accounts-payable clerk does by hand: does this bill match what we ordered, and is it safe to pay?

How the code is laid out

What it catches

PRICECharged more per unit than the order allows
QTYBilled for more than was ordered
MATHQuantity × price doesn't equal the line total
UNEXPECTEDA charge that is on no order at all
UNBILLEDSomething ordered that never got billed
SUBTOTALThe lines don't add up to the subtotal
TAXThe tax figure doesn't follow from the subtotal
TOTALSubtotal plus tax doesn't equal the total

A line can be wrong in two ways at once — mispriced and miscalculated — and the money must still be counted once. Overbilling is measured per line as billed minus authorised, never as the sum of the individual complaints. There is a regression test for exactly that.

Key Achievements

  • All of it — the interface, the two model calls, the audit engine, the prompts, the sample data and the tests.
  • Worked out where the model belongs. Doing the matching without an LLM fails on real documents; doing the arithmetic with one fails on real money. The system uses each for the half it is actually good at.
  • Stopped the model from being helpful. Early prompts quietly "fixed" a line where the arithmetic didn't work — erasing the very error the tool exists to find. The transcription step now forbids recomputation: copy what is printed, do not correct it.
  • Made it demonstrable with the AI switched off. Because the deciding half is a pure function, the sample run is not a canned screenshot — it is the real engine, executing.
